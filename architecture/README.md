# Architecture diagrams

This directory contains the public LikeC4 source used by EnergyAtlas Wiki architecture pages,
together with the connector router that produces their manual-layout geometry.

Every element, relationship, description, link, and comment in this directory is public
documentation. Models stay intentionally selective: add only concepts used by an approved
Wiki view, or reachable from one by drilldown.

Wiki pages render these views live. No diagram image is generated, referenced, or committed.

## Layout

- `likec4/` — the LikeC4 project: specification, model, views, and routing configuration.
- `tools/orthogonal-router/` — re-routes relationship connectors as strictly orthogonal paths
  with rounded corners, written as native `.likec4.snap` manual-layout files.
- `STYLE.md` — the visual contract every view is reviewed against.

## Install once

```bash
npm ci
```

## Build the live viewer

The three steps must run in order. The router writes snapshots into `likec4/.likec4/`, and
codegen bakes those snapshots into the viewer bundle, so a skipped or stale routing pass
silently publishes the wrong geometry.

```bash
npm run build
```

That runs `validate`, then `route`, then `viewer`, emitting
`../docs/assets/js/likec4-views.js`. Both the snapshots and the bundle are build outputs:
they are git-ignored and regenerated by CI on every deployment.

Run the steps individually when iterating:

```bash
npm run validate
```

```bash
npm run route
```

```bash
npm run viewer
```

## Interactive preview

```bash
npm start
```

This serves the LikeC4 project on its own with hot reload, which is the fastest way to
iterate on a model or view before rebuilding the Wiki. To preview a view exactly as the Wiki
serves it, run `npm run build` and then `mkdocs serve` from the repository root.

## Connector routing

LikeC4's own layout draws relationships as curved diagonal splines. The router re-routes them
into the whitespace Graphviz left behind, as strictly orthogonal paths joined by
quarter-circle corners. Node placement remains entirely Graphviz's.

Snapshots are geometry, not source. The router always rebuilds from pristine auto-layout, so
re-running it is safe and idempotent, and it is also how you discard an accidental drag in
the interactive preview. Per-view settings, including opting a view out, live in
[`likec4/routing.config.json`](likec4/routing.config.json); routing is on by default for
every view.

The router's geometry checker asserts that every emitted segment is axis-aligned or a
quarter-circle corner, and that no route crosses a node rectangle. It exits non-zero when a
route fails, which fails the deployment rather than publishing degraded diagrams.

To reset and regenerate a single view, leaving the others alone:

```bash
node tools/orthogonal-router/src/cli.mjs --workspace likec4 --view simulationDataFlow
```

To inspect the chosen routes for one view:

```bash
node tools/orthogonal-router/src/report.mjs likec4 simulationDataFlow
```

## Adding a view to the Wiki

1. Add the view to `likec4/views/architecture-views.c4`.
2. Run `npm run build` and confirm the router reports zero fallback edges and zero violations.
3. Embed it on a page under `docs/architecture/` with `likec4: true` in the front matter.
4. Run `pytest` from the repository root. The structural tests fail if a page references a
   view that does not exist, or if a primary view is published on more than one page.

Views reached only through drilldown do not need their own page, but every view in this
project must be reachable from a published page — either directly or through a `navigateTo`
chain.
